## Question

Should a UI be generated by default or selected explicitly?

## Resolution

Keep UI as an explicit optional Platform Capability. The default is `none`; supported choices can include Blazor and React, with additional variants introduced only after they have a tested contract.

## Rationale

UI technology affects authentication flows, deployment, client contracts, testing, and release cadence. Making it mandatory would burden API-only applications and couple the Platform Baseline to a volatile technology choice. An explicit capability seam preserves a consistent backend architecture while allowing supported UI variants.

## Alternatives considered

- Always generate Blazor. Rejected because UI is not universal and would bias all applications toward one hosting model.
- Always generate a JavaScript client. Rejected for the same reason and because it adds a second toolchain.
- Leave UI entirely undocumented. Rejected because optional capabilities still need declared integration seams and verification.

## Evidence

Explicitly requested and accepted during the Wayfinder charting interview.
